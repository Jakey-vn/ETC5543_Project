Automating Financial Account Creation

An R Pipeline for SOP-to-Database Reporting

Andy Tran

2026-05-13

Context & Motivation

The challenge

  • Financial accounts for two processing sites (Corowa & Laverton) were built manually each reporting period
  • Data lives across multiple spreadsheets with different structures
  • Manual process is time-consuming and error-prone
  • Any missed row = wrong account value

The goal

  • Build an automated R pipeline that reads raw SOP data and price files
  • Produces structured financial database entries covering every Business Unit
  • Includes a built-in quality check so errors can be caught before submission

Input Data Sources

File Contents Role in Pipeline
SOP Volumes.xlsx Weekly volumes by Farm / Bone / VA tabs Primary volume source
Prices.xlsb Carcass price, Kill fee, Bone fee, Item prices Value calculation
Master Data.xlsx GL accounts, Cost centre keys, Customer list Account structure
Trade Allowance.xlsx Trade discount rates per customer Expense accounts
Rates & Allocation.xlsx VA brand allocations, freight & storage rates Expense accounts

All files are read directly from a shared OneDrive folder so the pipeline always uses the latest version.

Pipeline Architecture

Revenue Accounts - Core Logic

Three steps are applied to every Business Unit:

Step 1 - Build account skeleton

# Pull all relevant customers from Master Data
# and attach the correct GL + Cost Centre key
account_rows <- customer_data %>%
  filter(BU == "1.Farming Operations") %>%
  left_join(gl_cc_data, by = "BU") %>%
  crossing(Period = 1:12)  # one row per month

Step 2 - Join SOP volume

# Match on SOP Unicode + Abattoir + Month + Tab
account_rows %>%
  left_join(volume_farm_raw,
            by = c("SOP Unicode" = "Unicode",
                   "Abattoir", "Month", "Tab"))

Step 3 - Calculate value

# Different formula per tab type
mutate(Value = case_when(
  Tab == "FARM" ~ Total_Weight * Carcass_Price,
  Tab == "KILL" ~ Units * Kill_Fee,
  Tab == "BONE" ~ Units * Bone_Fee
))

Key Challenges

Unstable source data

  • SOP Volumes contains spelling mistakes and inconsistent naming that silently break joins
  • Master Data missing customer or GL entries means volume rows match no account and are lost
  • Required ongoing fixes during development (e.g. str_trim, toupper, typo corrections)

Incomplete price data

  • Prices.xlsb frequently missing item codes - revenue rows for those items produce NA values
  • Packaging rates also missing for newer items - expense rows fail silently
  • Gap Check was built specifically to surface these missing-price rows after each run

Complex customer contracts

  • JBS negotiates individual discounts and special pricing per customer
  • Customers like Woolworths and DRJ require separate GL accounts and additional conditional calculation steps
  • Every new contract adds conditional logic, making the pipeline progressively harder to maintain

Quality Assurance - Gap Check

Built from real failure points during development - each check represents a problem that once caused silent data loss. Unlike manual Excel review, R pinpoints the exact item, month and site instantly.

Sheet 1 reconciles SOP raw weight vs database across 12 categories - a GAP status flags exactly which segment lost data. Sheet 2 lists every row that failed to enter the database:

Check What it catches
Item has no revenue price assigned New product not yet added to the price reference file
Item cannot be matched to a product category Incorrectly named value in the source data
Item missing storage type classification Missing Chilled / Frozen label in source data
Volume has no Carcass Price Customer volume with no matching carcass price
Volume has no Bone Processing Fee Customer volume with no matching bone fee
Volume has no Kill Fee Customer volume with no matching kill fee
Item sold at zero or missing price Sale record with blank or zero price
Internal vs external volume split does not reconcile Splitting logic error - totals don’t add up

Summary - Excel vs R

Excel (Before) R Pipeline (Now)
Time to build each month A lot of time for manual work per period One-click once - under 10 minutes
Adding a new Business Unit Copy, paste and reformat an entire sheet Add a filter condition and a join - minutes
Handling a rule change or new contract Manually update every affected cell Change one line of code, re-run
Data error tracing Manually scan rows - easy to miss Gap Check pinpoints exact item, month, site
Risk of human error High - copy-paste mistakes go unnoticed Low - same logic applied consistently every run
Complex freight cost allocation Averaged cost across all export types manually - imprecise and considered incorrect Many-to-many join assigns the correct rate to each specific export type automatically
Quality assurance Manual spot-check only Automated Gap Check runs after every build
